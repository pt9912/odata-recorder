**Vorgang:** slice-redaction-match-key
**Fund:** `SPEC-116` Nr. 8 sagte „ein anderes Geheimnis ergibt denselben Key“; für `Location` in `MATCH_VARY_HEADERS` war das falsch, der Wert ging unredigiert in den Key (Review-Befund F-1); behoben durch Code und Spezifikation (Vary-Werte aus der redigierten Darstellung, `TestKeyVaryRedigiert`). Die Allaussage der Einleitung „ein Aufrufer kann den Key nicht aus einer unredigierten Form bilden“ gilt für den Body nur als Kommentar und Zusage des Aufrufers (F-10), und zwei Plan-Zeilen sagten „alle Fälle“, wo die Tests über je eine Tabelle liefen (F-8).
